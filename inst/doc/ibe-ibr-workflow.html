1 What are IBE and IBR, and why fit them together?

Landscape geneticists commonly ask: why are some pairs of populations more genetically different than others? Two broad classes of explanation exist:

  • Isolation by resistance (IBR): genetic differentiation is associated with resistance distance derived from a covariate-parameterized conductance graph.
  • Isolation by environment (IBE): genetic differentiation is associated with environmental dissimilarity between sampled sites.

Both associations can occur at the same time and can be confounded. Fitting IBE and IBR terms concurrently estimates each coefficient conditional on the other term and the MLPE dependence structure. It does not causally allocate variation to distinct biological processes.

1.1 Where each process lives in the model

terradish places the two terms in different parts of one measurement model:

                           CONDUCTANCE SIDE
  Raster covariates   -->  loglinear_conductance  -->  resistance distances
  (altitude, forest)         theta parameters               R_ij

                           MEASUREMENT SIDE
  R_ij + endpoint          mlpe_covariates()      -->  genetic distances
  differences (Z_ij)       beta, gamma, rho_MLPE        S_ij

The mean structure of the joint model is:

\[S_{ij} = α + β · R_{ij} + Z_{ij} · γ + e_{ij}\]

where:

  • \(R_{ij}\) is the pairwise resistance distance (determined by the conductance surface and the θ parameters).
  • \(Z_{ij}\) is a pairwise endpoint-difference covariate (some measure of how environmentally dissimilar sites i and j are).
  • \(β\) describes the conditional IBR association: does resistance distance predict genetic differentiation after accounting for environment?
  • γ describes the conditional IBE association: does environmental mismatch predict genetic differentiation after accounting for landscape resistance?
  • \(e_{ij}\) is a residual following the MLPE correlation structure (see vignette("getting-started", package = "terradish")).

2 Prerequisites

This vignette assumes familiarity with the basic terradish workflow. If you have not yet read vignette("getting-started", package = "terradish"), start there.

3 Set up: data and scaled covariates

library(terradish)
library(terra)

data(melip)
melip.altitude    <- terra::unwrap(melip.altitude)
melip.forestcover <- terra::unwrap(melip.forestcover)
melip.coords      <- terra::unwrap(melip.coords)

# Scale continuous covariates before building the conductance surface.
# This keeps the conductance parameters on a comparable scale and avoids
# numerical overflow in exp(theta * x).
covariates <- c(melip.altitude, melip.forestcover)
names(covariates) <- c("altitude", "forestcover")
covariates <- scale_covariates(covariates)

surface <- conductance_surface(covariates, melip.coords, directions = 8)

4 Step 1: Construct IBE covariates

IBE operates at the level of pairs of sites. For each pair (i, j) we need a number that quantifies how environmentally different those two sites are. The helper pairwise_endpoint_covariates() computes this from site-level environmental values.

ibe_altitude <- melip.altitude
names(ibe_altitude) <- "altitude_site"

z_ibe <- pairwise_endpoint_covariates(
  ibe_altitude,            # site-level environmental data (raster or matrix)
  coords    = melip.coords,# focal-point locations (used to extract from raster)
  transform = "absdiff",  # how to convert site values into pairwise values
  scale     = TRUE         # standardize site values first
)

# Each row is one pair of sites; each column is one pairwise covariate.
dim(z_ibe)
#> [1] 666   1
head(z_ibe)
#>      absdiff_altitude_site
#> [1,]             0.5217511
#> [2,]             1.6264202
#> [3,]             0.6761406
#> [4,]             0.1773603
#> [5,]             1.1508445
#> [6,]             0.4351686

4.1 Choosing a pairwise transform

Four transforms are available:

Transform Formula When to use
"absdiff" |x_i − x_j| One covariate; symmetric, intuitive
"sqdiff" (x_i − x_j)² Penalizes large differences more; useful with noisy data
"euclidean" √Σ(x_ik − x_jk)² Multivariate environment; collapses to a single distance
"manhattan" Σ|x_ik − x_jk| Multivariate environment; less sensitive to outlier dimensions

Use "absdiff" (the default) for a single continuous covariate. For a multivariate environment (e.g. altitude + precipitation + temperature combined), "euclidean" or "manhattan" produce a single distance column that is easier to interpret and avoid inflating the model with many correlated predictors.

For two or more covariates treated separately, "absdiff" or "sqdiff" return one column per covariate:

# Example: separate absolute differences for altitude and forest cover
z_multi <- pairwise_endpoint_covariates(
  covariates,            # the two-layer scaled raster stack
  coords    = melip.coords,
  transform = "absdiff",
  scale     = FALSE      # already scaled in the raster
)
dim(z_multi)   # one column per layer
#> [1] 666   2
colnames(z_multi)
#> [1] "absdiff_altitude"    "absdiff_forestcover"

For this vignette we use altitude only (z_ibe) to keep the IBE side simple and interpretable.

5 Step 2: Build the joint measurement model

mlpe_covariates() wraps the pairwise covariates into an MLPE measurement model. The resulting object (g_ibe) can be passed anywhere that mlpe can: terradish(), terradish_grid(), and terradish_cv().

g_ibe <- mlpe_covariates(z_ibe)

g_ibe is a function, not a fitted model; it defines the likelihood structure. The actual parameters (β, γ, and the MLPE correlation) are estimated when you call terradish().

6 Step 3: Fit the four candidate models

To compare conditional support for IBR and IBE terms, fit all four combinations. These models do not uniquely attribute genetic structure to either process.

# NewtonRaphsonControl limits the number of optimizer iterations.
# The vignette caps maxit at 20. In an applied analysis, allow convergence and
# verify optimizer diagnostics rather than relying on this illustrative cap.
ctrl <- NewtonRaphsonControl(maxit = 20, verbose = FALSE)

# IBD: null model, no landscape or environment predictors
fit_ibd <- terradish(
  melip.Fst ~ 1,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = mlpe,
  leverage          = FALSE,
  control           = ctrl
)

# IBE only: environmental mismatch, but no landscape resistance
fit_ibe <- terradish(
  melip.Fst ~ 1,           # no raster covariates on the conductance side
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = g_ibe, # IBE is on the measurement side
  leverage          = FALSE,
  control           = ctrl
)

# IBR only: landscape resistance, no environmental mismatch
fit_ibr <- terradish(
  melip.Fst ~ altitude + forestcover,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = mlpe,
  leverage          = FALSE,
  control           = ctrl
)

# Joint IBE + IBR: both processes in a single model
fit_joint <- terradish(
  melip.Fst ~ altitude + forestcover,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = g_ibe,
  leverage          = FALSE,
  control           = ctrl
)

Note on leverage = FALSE: By default, terradish() computes influence/leverage diagnostics for each observation, which requires additional linear-algebra work. Setting leverage = FALSE skips this step to reduce run time. For a final analysis where you want diagnostics, set this argument to TRUE.

7 Step 4: Interpret the joint model

7.1 Conductance parameters (theta)

coef() returns the θ values that map raster covariates to fitted relative conductance:

coef(fit_ibr)   # IBR-only model
#>    altitude forestcover 
#> -0.49818394  0.08470684
coef(fit_joint) # joint model (theta side only)
#>    altitude forestcover 
#>  -0.5196237   0.1431812

Interpretation is the same as in any IBR model: a positive θ means higher covariate values are associated with higher fitted relative conductance, conditional on the other terms and graph; a negative θ means lower fitted relative conductance. These coefficients do not directly measure movement, permeability, or a causal barrier. See vignette("getting-started", package = "terradish") for conductance ratios.

Notice that the θ estimates may shift between fit_ibr and fit_joint. That is expected: when the joint model can attribute some of the pairwise variation to environmental mismatch (γ), it no longer needs the IBR coefficients to carry that variation.

7.2 IBE coefficients (gamma, inside phi)

Look for the row named absdiff_<layer>_site in the phi table. A positive γ means that sites with greater altitude differences are more genetically different, after accounting for the resistance distance between them. A negative γ (rarely biologically expected for IBE) would mean the opposite.

The summary table also reports confidence intervals for the nuisance parameters, including the IBE coefficient. These intervals are conditional on the fitted conductance surface, so they should be interpreted as uncertainty in the MLPE regression layer after the IBR surface has been estimated.

summary(fit_joint)$phi_table["absdiff_altitude_site", ]
#>    Estimate  Std. Error   Lower 95%   Upper 95% 
#> 0.013109805 0.001166119 0.010824254 0.015395356

Because γ is on the response scale, it is often easier to interpret as the expected change in genetic distance across a meaningful change in the pairwise covariate. mlpe_response_change() does this calculation using the pairwise covariates stored in the fitted measurement model. By default, it compares the 90th and 10th percentiles:

mlpe_response_change(fit_joint)
#>               covariate        low     high contrast   estimate   conf.low
#> 1 absdiff_altitude_site 0.08887153 2.336687 2.247815 0.02946842 0.02433092
#>    conf.high conf.level
#> 1 0.03460591       0.95

The estimate column is the expected change in pairwise genetic distance over that covariate contrast, after accounting for the fitted resistance distance. For a custom contrast, provide explicit low and high values:

mlpe_response_change(fit_joint,
                     covariate = "absdiff_altitude_site",
                     values = c(0, 2))
#>               covariate low high contrast   estimate   conf.low  conf.high
#> 1 absdiff_altitude_site   0    2        2 0.02621961 0.02164851 0.03079071
#>   conf.level
#> 1       0.95

The other phi parameters (alpha, beta, tau, rho) are the same as in a plain mlpe fit: intercept, IBR slope, log precision, and an unconstrained correlation parameter. Transform the last two to residual precision with exp(tau) and to the shared-site correlation with plogis(rho) / 2.

7.3 Quick summary of which parameter lives where

Parameter Symbol Where it appears What it measures
Conductance θ coef(fit) Conditional association between raster covariates and fitted relative conductance
IBR slope β (beta) summary(fit)$phi How resistance distance predicts genetic distance
IBE slope γ (absdiff_*_site) summary(fit)$phi How environmental mismatch predicts genetic distance
IBE response change γ ΔZ mlpe_response_change(fit) Expected genetic-distance change across a pairwise-covariate contrast
Intercept α (alpha) summary(fit)$phi Baseline genetic distance at zero resistance
Residual precision exp(τ) (tau) summary(fit)$phi Inverse residual variance
MLPE correlation plogis(ρ)/2 (rho) summary(fit)$phi Shared-site correlation in pairwise residuals

8 Step 5: Compare the model set

8.1 Information criteria

aic_table() ranks these four models because they use the same response, sites, graph domain, Gaussian likelihood family, and full pair set:

aic_table(
  list(fit_ibd, fit_ibe, fit_ibr, fit_joint),
  mod_names = c("IBD", "IBE only", "IBR only", "IBE + IBR (joint)")
)
#>               model K       AIC Delta_AIC AIC_wt Cum.wt   loglik
#> 4 IBE + IBR (joint) 7 -4409.951    0.0000      1      1 2211.976
#> 3          IBR only 6 -4298.770  111.1816      0      1 2155.385

A lower AIC indicates a better balance of fit and parsimony. The delta column shows how far each model is from the best. Models within 2 AIC units of the best are generally considered to have comparable support.

Note that IBE-only (fit_ibe) and IBR-only (fit_ibr) are not nested in each other; they differ on which side of the model (conductance vs. measurement) carries the predictors. Use aic_table(), not anova(), to compare them.

8.3 Cross-validation for predictive comparison

cv_model_selection() combines held-out log-likelihoods with an AIC table so you can compare models on both in-sample fit and out-of-sample prediction.

terradish_cv() requires at least one conductance parameter, so this helper can be called for the IBR-only and joint models. The IBD and IBE-only models use ~ 1 and are not evaluated by this workflow. Do not substitute in-sample log-likelihood for held-out likelihood; those quantities are not comparable.

cv_ctrl <- NewtonRaphsonControl(maxit = 15, verbose = FALSE)

# IBR-only: has conductance parameters, so held-out evaluation is supported
cv_ibr <- terradish_cv(
  pts = melip.coords, covariates = covariates,
  fmla = melip.Fst ~ altitude + forestcover, model = mlpe,
  prop_train = 2 / 3, seed = 1, fit_full = TRUE,
  control = cv_ctrl
)

# Joint IBE + IBR: uses the same held-out split
cv_joint <- terradish_cv(
  pts = melip.coords, covariates = covariates,
  fmla = melip.Fst ~ altitude + forestcover, model = g_ibe,
  prop_train = 2 / 3, seed = 1, fit_full = TRUE,
  control = cv_ctrl
)

# Compare only models evaluated on held-out data from the same split.
comparison <- cv_model_selection(
  list(
    list(train_mod = cv_ibr$train_mod,
         cv_loglik  = cv_ibr$cv_loglik,
         full_mod   = cv_ibr$full_mod),
    list(train_mod = cv_joint$train_mod,
         cv_loglik  = cv_joint$cv_loglik,
         full_mod   = cv_joint$full_mod)
  ),
  cv_names = c("IBR only", "IBE + IBR (joint)"),
  aic = TRUE
)

# Held-out log-likelihood (higher is better predictive performance)
comparison$loglik_tab
#>               model K   loglik  Delta_LL
#> 2 IBE + IBR (joint) 7 219.7550  0.000000
#> 1          IBR only 6 215.5317 -4.223335

# AIC table from the full-data fits
comparison$AIC_tab
#>                             model K       AIC Delta_AIC AIC_wt Cum.wt   loglik
#> 2 altitude + forestcover [mlpe:1] 7 -4409.951    0.0000      1      1 2211.976
#> 1          altitude + forestcover 6 -4298.770  111.1816      0      1 2155.385

Why cross-validate? AIC summarizes in-sample likelihood with a complexity penalty. Cross-validation evaluates held-out predictive likelihood. Random site splits can leak information across spatial clusters, so use folds aligned with the intended prediction target when transfer to new regions or clusters is the goal.

For a more stable estimate of predictive performance, repeat across multiple random splits using terradish_cv_replicates():

cv_joint_reps <- terradish_cv_replicates(
  pts        = melip.coords,
  covariates = covariates,
  fmla       = melip.Fst ~ altitude + forestcover,
  model      = g_ibe,
  seeds      = 1:5,
  fit_full   = FALSE,
  keep_fits  = FALSE,
  control    = cv_ctrl
)

summary(cv_joint_reps)

10 Step 7: Saved-results utilities

Some workflows fit terradish models once, save them to disk, and later extract summaries. Two helpers support this pattern.

terradish_results() inspects a terradish-style results directory and recovers the fitted objects and metadata stored there:

# Create a temporary directory to illustrate the pattern.
tmp_dir <- tempfile("terradish-results-")
dir.create(tmp_dir)

# Save the joint fit and a minimal AllResults object.
saveRDS(fit_joint, file.path(tmp_dir, "fit--mlpe.rds"))
saveRDS(
  list(
    effect_size = coef(fit_joint),
    pts         = melip.coords,
    covariates  = covariates
  ),
  file.path(tmp_dir, "AllResults_list.rds")
)

results_info <- terradish_results(tmp_dir)
names(results_info)
#> [1] "all_results" "all_dirs"    "pts"         "covariates"  "effect_size"

terradish_parameters() extracts a compact coefficient table from a saved fitted model. This is useful in simulation studies where you want to compare generating coefficients with estimated values across many saved runs:

parameter_table <- terradish_parameters(

11 Alternative approach: Wishart-based IBE with wishart_covariates()

The mlpe_covariates() approach in Steps 1-7 adds environmental terms to the mean structure of an MLPE regression. A conceptually different route adds environmental information to the covariance structure of a Wishart likelihood model. Use this alternative when:

  • You are using generalized_wishart (an admissible squared-distance response with known effective nu) or wishart_covariance (a positive semidefinite covariance-matrix response).
  • You have a known effective marker degrees-of-freedom value (nu) to supply as the Wishart degrees-of-freedom parameter.
  • The response is admissible for the chosen Wishart representation and you want a full-matrix covariance-kernel likelihood rather than an MLPE mean regression.

wishart_covariates() is the direct Wishart analogue of mlpe_covariates(). Instead of adding pairwise environmental dissimilarities as regression covariates, it builds an outer-product kernel \({K_k = z_k z_k^\top}\) for each site-level environmental covariate and adds it to the fitted covariance matrix:

\[\Sigma = \tau E(\theta) + \sum_k \lambda_k K_k + \exp(\sigma) I\]

Do not use pair_subset_measurement_model() for this workflow. That helper selects pair rows for distance-regression models such as leastsquares and mlpe. Wishart models evaluate the full response matrix likelihood, so the environmental term needs to enter as a full site-by-site kernel through wishart_covariates().

A positive \({\lambda_k}\) adds positive covariance along the specified environmental kernel after the graph covariance. This kernel weight is not numerically comparable to the MLPE slope \({\gamma}\) and does not establish a causal environmental process.

11.1 Building the Wishart IBE measurement model

The code below constructs an admissible squared-distance response from a simulated positive semidefinite covariance matrix, then shows the generalized_wishart API. For real data, being labeled a distance matrix is not sufficient. Establish that the response is admissible for the centered covariance representation, or use "wishart_covariance" with a positive semidefinite covariance matrix from cov_from_genetic_data().

nu_demo <- 50
sim_wishart <- simulate_covariance_response(
  theta   = c(altitude = 0.35, forestcover = -0.25),
  formula = ~ altitude + forestcover,
  data    = surface,
  tau     = 0.8,
  sigma   = 0.2,
  nu      = nu_demo,
  seed    = 2026
)
S_wishart <- dist_from_cov(sim_wishart$covariance)

11.2 Fitting the four Wishart candidate models

Wishart models require nu as the effective degrees-of-freedom parameter. It is not estimated. For biallelic SNPs, use the number of approximately independent retained SNPs. For microsatellites, use the number of loci as the conservative primary value and examine sum(K_l - 1) only as a larger sensitivity value. Here, nu_demo is the simulation degrees of freedom and is held fixed across all candidate fits. It is not a claim about the effective information in the bundled Melipona data.

# Wishart IBD: null conductance, no environmental kernels
fit_w_ibd <- terradish(
  S_wishart ~ 1,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = generalized_wishart,
  nu                = nu_demo,
  leverage          = FALSE,
  control           = ctrl
)

# Wishart IBE only: altitude kernel, uniform conductance
fit_w_ibe <- terradish(
  S_wishart ~ 1,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = g_wishart_ibe,
  nu                = nu_demo,
  leverage          = FALSE,
  control           = ctrl
)

# Wishart IBR only: landscape covariates, no environmental kernel
fit_w_ibr <- terradish(
  S_wishart ~ altitude + forestcover,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = generalized_wishart,
  nu                = nu_demo,
  leverage          = FALSE,
  control           = ctrl
)

# Wishart joint: landscape covariates + altitude IBE kernel
fit_w_joint <- terradish(
  S_wishart ~ altitude + forestcover,
  data              = surface,
  conductance_model = loglinear_conductance,
  measurement_model = g_wishart_ibe,
  nu                = nu_demo,
  leverage          = FALSE,
  control           = ctrl
)

The phi table contains three types of nuisance parameters that are quite different from the MLPE table:

  • tau: nonnegative weight on the graph covariance kernel. Near zero means no detectable graph-kernel contribution under this response and model.
  • lambda_altitude: nonnegative weight on the altitude covariance kernel.
  • sigma: log-scale nugget (\(\exp(\sigma) I\) on the diagonal), representing diagonal variation not captured by the graph and environmental kernels.

There is no alpha, beta, or rho because the Wishart model does not have an MLPE regression layer. The fitted covariance is parameterized through these components, but they need not uniquely identify biological sources of variation.

11.5 Choosing between mlpe_covariates() and wishart_covariates()

Aspect mlpe_covariates() wishart_covariates()
Response Distance matrix (nu not required) Distance or covariance matrix; nu required
Environmental term Regression covariate in mean structure Covariance-kernel component
IBE parameter γ (linear slope; any sign) λ (kernel weight; ≥ 0)
IBE interpretation Environmental mismatch shifts mean distance Environmental similarity increases shared covariance
Requires effective nu No Yes
anova() applicable Yes, for nested models Yes, for nested Wishart models

If effective nu and an admissible response representation are defensible and a covariance-kernel model matches the question, use wishart_covariates(). If nu is unavailable or a conditional mean-distance slope is the target, use mlpe_covariates().

12 Putting it all together: a decision guide

Goal Recommended approach
Does landscape resistance matter? anova(fit_ibr, fit_ibd)
Does environment matter after accounting for resistance? anova(fit_joint, fit_ibr), or inspect γ in summary(fit_joint)
Which single model has the best in-sample fit? aic_table(list(...))
Which model predicts new sites best? cv_model_selection(list(...))
Is my predictive result stable across splits? terradish_cv_replicates()
What is the fitted landscape surface? conductance(surface, fit_joint)

The joint model is most useful when you suspect both IBE and IBR are operating. If the γ estimate is near zero with a wide standard error, the IBE term is not adding explanatory power and the simpler IBR model is preferable.

# 2a. MLPE approach: build IBE covariates and measurement model

  melip.altitude, coords = melip.coords,
  transform = "absdiff", scale = TRUE
)
g_ibe <- mlpe_covariates(z_ibe)

# 3. Fit IBD, IBE, IBR, and joint models (MLPE)

                       surface, loglinear_conductance, g_ibe)

                       surface, loglinear_conductance, mlpe)

                       surface, loglinear_conductance, g_ibe)

# 4. Compare
